# Store a current snapshot and append-only timeline

Each Match will persist its current lifecycle state, Position, Turn, deadlines, expiry, and Match Revision in a primary row, while Readiness, accepted Moves, and Match Outcome are appended to separate history tables. This avoids the read cost and reconstruction complexity of full event sourcing without collapsing permanent history into a mutable JSON document; every accepted state change updates the snapshot and appends its history inside one Postgres transaction. Rejected Moves and technical errors are returned as transient feedback and are not appended to the permanent Match Timeline.
